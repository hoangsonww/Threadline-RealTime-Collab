## Project skills

This repository ships skills under [`.claude/skills/`](.claude/skills/). Invoke the relevant one **before** starting the corresponding work, not after getting stuck:

| Skill | Use it when |
| --- | --- |
| `threadline-api-endpoint` | Adding or changing an HTTP route in `apps/api` |
| `threadline-realtime-event` | Changing the Durable Object message protocol in `apps/realtime` |
| `threadline-trust-boundary` | Any change that touches authorization, tickets, secrets, or cross-service trust |
| `threadline-adr` | The change is an architectural decision and needs a record |
| `threadline-local-stack` | Running, verifying, or debugging the three services locally |
| `threadline-ship` | Preparing a change for review and merge |

## Working style in this repository

**Read before writing.** `apps/api/src/application.ts` is ~1,800 lines and `openapi.ts` is ~1,500. Grep for the route or symbol you need and read its surrounding region rather than loading whole files — but do read enough context to match the local pattern, because matching it is a review criterion.

**Prefer the repository's own tooling over ad-hoc shell.** `npm run doctor` before assuming the environment is fine. `make help` lists every task. `npm run docs:links` after editing any heading. These exist so you do not have to reconstruct what "verified" means.

**Verification is not optional and not inferable.** Run the check that proves the specific claim you are about to make, and report the command and its result. "The types should be fine" is not a verification. If you genuinely cannot run something — no Docker, no cluster — say which check you skipped and why, rather than omitting it.

**Scope discipline.** Change what was asked. Adjacent code that looks improvable is not part of the task; mention it instead of fixing it. This repository's review standard treats unsolicited refactoring as a defect in the change, not a bonus.

**Push back when warranted.** If a requested change would violate one of the invariants in `AGENTS.md` — most often "remove this check, the other service already does it" — say so plainly, explain the specific consequence, and propose the alternative. Do not implement it quietly and note the concern afterwards.

## Things that are easy to get wrong here

- The three services **re-verify each other on purpose**. A check that looks duplicated is almost certainly load-bearing. Read [`docs/security.md`](docs/security.md) before removing one.
- `MemoryRepository` and `MongoRepository` must both implement any new `Repository` method. Implementing one is a silent break, and which half is broken depends on whether you are looking at tests or production.
- `Cache` (`apps/api/src/cache.ts`) is a **separate port from `Repository`**, not an extension of it. Everything behind it is evictable and may throw, so a call site without a fallback is a bug — and the fallback must do *more* work, never enforce less. Nothing authorization-related is ever cached. `redis` is importable only from that file, exactly as `mongodb` is only importable from `repository.ts`. See [ADR 0009](docs/decisions/0009-redis-for-ephemeral-counters.md).
- `createRedisCache()` must never `await` the connection. `node-redis` retries instead of rejecting an unreachable server, so awaiting it blocks the API's boot forever. This was a real bug; the ADR records it.
- A new endpoint needs a test for its **403**, not only its 200.
- Prettier deliberately does not format `*.md`. Do not reformat markdown.
- `worker-configuration.d.ts` is generated by `wrangler types` during `npm run typecheck --workspace=@threadline/realtime`. A diff in it is regeneration noise — do not commit it as though it were a change, and never hand-edit it.

## Definition of done

The checklist in [`AGENTS.md`](AGENTS.md#definition-of-done) is the standard. The short version: `npm run check` passes, the denied path is tested, `docs/` is updated in the same change, and you have said what you ran.
